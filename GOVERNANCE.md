# Governance

Themis is currently maintainer-led. Maintainers decide releases and merge changes after public review, with scientific correctness, reproducibility, backward compatibility, and documented scope taking priority over feature volume.

Substantial benchmark, metric, artifact-schema, or protocol-contract changes should begin with a GitHub issue describing the research need, alternatives, compatibility effect, validation plan, and ownership. Decisions and dissent should remain in the public issue or pull request when security or privacy does not prevent it.

As the contributor base grows, this document should name maintainers, decision thresholds, release authority, conflict-of-interest handling, and a succession process. Current maintainer status must not be interpreted as independent scientific validation.
